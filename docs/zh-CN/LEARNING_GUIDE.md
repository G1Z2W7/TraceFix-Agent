# 项目学习指南

这个项目把每个 Pull Request 设计成一个学习单元。你需要运行功能、观察真实状态，并用自己的话解释设计，而不是只阅读生成的代码。

## 每个 Pull Request 开始前

1. 阅读关联 Issue 的问题、范围和非目标。
2. 画出数据流和状态所有者。
3. 预测一个失败场景的结果。
4. 确认验收命令和学习目标。

## 实现过程中

1. 先运行一个失败的边界测试。
2. 实现能让测试通过的最小变更。
3. 检查真实状态，例如数据库记录、Redis 键、RabbitMQ 队列、LangGraph Checkpoint 或 Langfuse Trace。
4. 完成该 PR 指定的动手练习。
5. 把超出范围的问题记录为新的 Issue。

## 审核前

你需要完成以下任务：

- 运行 PR 中列出的验收命令。
- 解释三个重要类型或函数的职责。
- 说明一个失败模式和对应防护。
- 判断是否存在更小的实现。
- 检查回滚方式。

## 合并后

1. 在 `main` 上运行冒烟测试。
2. 在 `docs/learning/` 中记录本次学习结果。
3. 分别写出“我能解释”“我能运行”和“我能排查”的内容。
4. 在里程碑结束时调整后续路线。

## 技术学习顺序

| 阶段 | 技术 | 需要掌握的结果 |
| --- | --- | --- |
| 工程骨架 | Python、FastAPI、Docker | 能从请求追踪到数据库连接 |
| Order Sandbox | PostgreSQL、Redis、RabbitMQ | 能解释事务、幂等、重试和死信队列 |
| FlowPilot | RAG、LangChain、LangGraph | 能解释检索、工具 Schema 和状态恢复 |
| Agent 观测 | Langfuse | 能从 Trace 定位一次真实失败 |
| TraceFix | 回放、评测、版本门禁 | 能判断修复是否引入回归 |
| 开源接入 | CLI、Skill、契约测试 | 能审核另一个 Agent 的接入证据 |
